# DeMark — сторінка реєстрації відвідувачів

Next.js 14 (App Router) + Supabase + Vercel.

- `/register` — публічна форма реєстрації відвідувачів магазину
- `/admin` — захищена панель для перегляду, пошуку, фільтрації зібраних даних та розсилок
- `/app` — персональний кабінет відвідувача (PWA): свої дані + стрічка розсилок

## Що зібрано в формі реєстрації

- **Ім'я**
- **Телефон** — через Contact Picker API (кнопка «поділитись номером з контактів»). Це нативний браузерний API, який дозволяє обрати номер зі списку контактів пристрою без ручного вводу.
  - ⚠️ Наразі підтримується лише в Chrome/Edge на **Android**. У Safari (iOS) та на десктопі цей API відсутній — форма автоматично показує запасний варіант зі звичайним полем `tel` (з `autocomplete="tel"`, щоб браузер міг підказати збережений номер). Це обмеження самого браузера, а не цього коду — жоден сайт не може обійти його інакше.
- **Геопозиція** — через `navigator.geolocation`. На основі координат:
  - автоматично визначається найближчий магазин з 5 заданих точок (формула гаверсинуса);
  - якщо відстань до найближчого магазину **≤ 200 м** — місто й магазин підставляються автоматично;
  - якщо відстань **> 200 м** (GPS неточний / людина не в магазині) — показується попередження, і відвідувач підтверджує чи обирає магазин вручну зі списку (це відмічається в базі полем `store_confirmed_manually`).
- **Вік**: 16-24, 25-35, 36-45, 46-55, 56+
- **Стать**: чоловік / жінка / не хочу зазначати

## Знижка 10% за реєстрацію

Після успішної реєстрації відвідувач бачить постійний (не зникає, без таймера)
екран зі знижкою -10%, який потрібно показати продавцю на касі.

Знижка одноразова на людину: номер телефону нормалізується (залишаються лише
цифри, береться останні 9) і на нього стоїть унікальний індекс у БД
(`phone_normalized`, `supabase/schema.sql`). Якщо людина з тим самим номером
реєструється вдруге — insert падає з помилкою `23505` (unique violation),
і форма замість "дякуємо" показує "знижку вже використано". Саме тому в формі
важливо отримати справжній номер (через Contact Picker або ручний ввід), а не
довільний — це і є механізм захисту від повторного використання знижки.

## Особистий кабінет / PWA / push-розсилки

Після отримання знижки відвідувач може натиснути «встановити застосунок і
отримувати новини» — це веде на `/app`, персональний кабінет DeMark:

- **Ідентифікація без логіну/пароля.** При реєстрації браузер генерує
  випадковий `access_token` (`crypto.randomUUID()`), який зберігається в
  `localStorage` пристрою і як колонка в БД. `/app` показує дані лише того,
  чий токен збігається — server-side, через `SUPABASE_SERVICE_ROLE_KEY`
  (обходить RLS, тому anon-ключ так само не може читати чужі рядки).
  Обмеження: якщо людина очистить дані сайту чи перевстановить застосунок —
  токен губиться, і треба реєструватись заново (свідомий компроміс заради
  простоти й безпеки, без окремого механізму відновлення за номером
  телефону — це відкрило б спосіб підбору чужих даних за номером).
- **Встановлення на головний екран.** У Chrome/Android є нативний
  системний диалог встановлення (`beforeinstallprompt`). У Safari/iOS
  Apple **свідомо не дає жодного програмного API** для встановлення — це
  обмеження платформи, обійти його неможливо жодним кодом. Тому на iOS
  `/app` показує текстову інструкцію: «Поділитись» → «На екран Домівка».
- **Push-сповіщення** — через Web Push (VAPID), кнопка «увімкнути
  сповіщення» в `/app`. На iOS Push працює **лише** зі встановленого на
  головний екран застосунку (Safari 16.4+) — у звичайній вкладці браузера
  Apple його не підтримує.
- **Розсилки** адмін створює й надсилає з вкладки «розсилки» в `/admin`:
  заголовок, текст, необов'язкове посилання, фільтри аудиторії (місто,
  магазин, вік, стать). Відправка — реальний Web Push через серверний
  роут `app/api/admin/send-notification` (ключ `VAPID_PRIVATE_KEY`
  ніколи не потрапляє в браузер). У `/app` та ж розсилка з'являється в
  стрічці «новини» (нові зверху, посилання клікабельні) — фільтрується на
  сервері під профіль конкретної людини.

## Стилістика

Кольори звірені напряму з офіційного сайту demark.ua (не підібрані на око):
семпл пікселів логотипу сайту дав фірмовий графітовий `#434445` і білий,
а з CSS сайту витягнуто `#EEEEEE` (секції/роздільники) та `#DF3131`
(червоний акцент, яким на сайті позначені знижки/акції — тому в цьому проєкті
він використаний саме для екрана "-10%"). Ці значення — в одному місці,
`tailwind.config.ts`.

Лого — оригінальний вордмарк "DEMARK" (вектор, витягнутий із сайту
demark.ua) у `components/Logo.tsx`, і кругла монограма D·M з favicon сайту —
у `app/icon.png` (іконка вкладки браузера).

Шрифти сайту — комерційні (Kepler для заголовків, DIN Next/Helvetica Neue
для тексту), недоступні через Google Fonts. Замінені найближчими
безкоштовними відповідниками за характером: `Cormorant Garamond` (елегантний
serif) для заголовків + `Inter` (нейтральний geometric sans) для інтерфейсу —
обидва в `app/layout.tsx`. Якщо колись з'явиться доступ до ліцензій на
оригінальні шрифти — заміна відбувається в цьому ж файлі.

## 1. Налаштування Supabase

1. Створіть проєкт на [supabase.com](https://supabase.com).
2. Відкрийте **SQL Editor → New query**, вставте вміст файлу `supabase/schema.sql` і виконайте (створить таблицю `registrations`, індекси, унікальність номера телефону для одноразової знижки та RLS-політики: анонімні відвідувачі можуть лише додавати записи, читати може лише автентифікований адміністратор).

   Якщо таблиця `registrations` вже існує (проєкт запускався раніше) —
   виконайте окремо лише відсутні шматки. Кожен блок можна запускати
   повторно (`if not exists`), тож просто виконайте весь `schema.sql`
   ще раз — нічого не зламає вже наявні дані.
3. Створіть обліковий запис адміністратора: **Authentication → Users → Add user**, вкажіть email і пароль співробітника, який матиме доступ до `/admin`. Додайте стільки акаунтів, скільки потрібно людей з доступом.
4. Скопіюйте з **Project Settings → API**:
   - **Project URL** та **anon public key** — знадобляться в кроці 2 нижче;
   - **service_role key** (секретний, під "Reveal") — знадобиться як
     `SUPABASE_SERVICE_ROLE_KEY`. **Ніколи** не додавайте його з префіксом
     `NEXT_PUBLIC_` і не показуйте в клієнтському коді — на відміну від
     anon-ключа, він повністю обходить RLS.

## 2. Локальний запуск

```bash
npm install
cp .env.example .env.local
# вставте у .env.local значення NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY /
# SUPABASE_SERVICE_ROLE_KEY (крок 1.4 вище)
npm run dev
```

Для push-розсилок (не обов'язково для базового `/register` + `/admin`)
потрібна ще пара VAPID-ключів — згенеруйте один раз:
```bash
npx web-push generate-vapid-keys
```
і впишіть результат у `.env.local` як `NEXT_PUBLIC_VAPID_PUBLIC_KEY` /
`VAPID_PRIVATE_KEY`.

Відкрийте `http://localhost:3000/register` та `http://localhost:3000/admin`.

## 4. Деплой на Vercel

1. На [vercel.com](https://vercel.com) → **Add New → Project** → імпортуйте щойно створений GitHub-репозиторій.
2. У розділі **Environment Variables** додайте всі змінні з `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (якщо є push-розсилки)
3. Deploy. Vercel автоматично визначить Next.js і збере проєкт.
4. Прив'яжіть свій домен у **Project → Settings → Domains**.

Після цього кожен `git push` в `main` буде автоматично деплоїти оновлення.

## Примітки з безпеки

- `anon key` Supabase призначений для публічного використання в браузері — це нормально, безпека забезпечується політиками Row Level Security (RLS), а не приховуванням ключа.
- Анонімні відвідувачі можуть **лише додавати** записи (`insert`), не можуть читати чи змінювати чужі дані.
- Читати список реєстрацій може лише той, хто увійшов через `/admin` під обліковим записом Supabase Auth.
- Геопозиція та номер телефону відвідувача — персональні дані. Перед запуском рекомендується додати на форму реєстрації коротке пояснення, навіщо збираються дані, і за потреби — окрему згоду на обробку персональних даних (checkbox) відповідно до вимог законодавства про захист персональних даних.
- `SUPABASE_SERVICE_ROLE_KEY` та `VAPID_PRIVATE_KEY` — секрети рівня сервера. Вони використовуються лише в `app/api/**/route.ts` і `lib/supabaseAdmin.ts`/`lib/webpush.ts`; ніколи не імпортуйте ці файли в клієнтські (`"use client"`) компоненти.
- Push-сповіщення вмикаються лише за явним дозволом відвідувача (системний запит браузера) — без нього підписка не створюється.
