# DeMark — сторінка реєстрації відвідувачів

Next.js 14 (App Router) + Supabase + Vercel.

- `/register` — публічна форма реєстрації відвідувачів магазину
- `/admin` — захищена панель для перегляду, пошуку та фільтрації зібраних даних

## Що зібрано в формі реєстрації

- **Ім'я**
- **Телефон** — через Contact Picker API (кнопка «поділитись номером з контактів»). Це нативний браузерний API, який дозволяє обрати номер зі списку контактів пристрою без ручного вводу.
  - ⚠️ Наразі підтримується лише в Chrome/Edge на **Android**. У Safari (iOS) та на десктопі цей API відсутній — форма автоматично показує запасний варіант зі звичайним полем `tel` (з `autocomplete="tel"`, щоб браузер міг підказати збережений номер). Це обмеження самого браузера, а не цього коду — жоден сайт не може обійти його інакше.
- **Геопозиція** — через `navigator.geolocation`. На основі координат:
  - автоматично визначається найближчий магазин з 5 заданих точок (формула гаверсинуса);
  - якщо відстань до найближчого магазину **≤ 200 м** — місто й магазин підставляються автоматично;
  - якщо відстань **> 200 м** (GPS неточний / людина не в магазині) — показується попередження, і відвідувач підтверджує чи обирає магазин вручну зі списку (це відмічається в базі полем `store_confirmed_manually`).
- **Вік**: 16-24, 25-35, 36-45, 46-55, 56+
- **Стать**: чоловік / жінка / не хочу зазначати

## Стилістика

Оформлення орієнтоване на візуальний стиль demark.ua (мінімалізм, багато повітря, теплий білий фон, майже чорний текст, золотисто-бежевий акцент для кнопок, елегантний serif для заголовків + geometric sans для інтерфейсу). Кольори й шрифти — найкраще наближення без прямого доступу до фірмового брендбуку; якщо у вас є точні HEX-коди чи назви шрифтів з дизайн-системи DeMark, поміняйте їх в одному місці — `tailwind.config.ts` (кольори) та `app/layout.tsx` (шрифти Google Fonts `Cormorant Garamond` + `Jost`).

## 1. Налаштування Supabase

1. Створіть проєкт на [supabase.com](https://supabase.com).
2. Відкрийте **SQL Editor → New query**, вставте вміст файлу `supabase/schema.sql` і виконайте (створить таблицю `registrations`, індекси та RLS-політики: анонімні відвідувачі можуть лише додавати записи, читати може лише автентифікований адміністратор).
3. Створіть обліковий запис адміністратора: **Authentication → Users → Add user**, вкажіть email і пароль співробітника, який матиме доступ до `/admin`. Додайте стільки акаунтів, скільки потрібно людей з доступом.
4. Скопіюйте **Project URL** та **anon public key** з **Project Settings → API** — вони знадобляться в кроці 3.

## 2. Локальний запуск

```bash
npm install
cp .env.example .env.local
# вставте у .env.local значення NEXT_PUBLIC_SUPABASE_URL / NEXT_PUBLIC_SUPABASE_ANON_KEY
npm run dev
```

Відкрийте `http://localhost:3000/register` та `http://localhost:3000/admin`.

## 4. Деплой на Vercel

1. На [vercel.com](https://vercel.com) → **Add New → Project** → імпортуйте щойно створений GitHub-репозиторій.
2. У розділі **Environment Variables** додайте:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. Deploy. Vercel автоматично визначить Next.js і збере проєкт.
4. Прив'яжіть свій домен у **Project → Settings → Domains**.

Після цього кожен `git push` в `main` буде автоматично деплоїти оновлення.

## Примітки з безпеки

- `anon key` Supabase призначений для публічного використання в браузері — це нормально, безпека забезпечується політиками Row Level Security (RLS), а не приховуванням ключа.
- Анонімні відвідувачі можуть **лише додавати** записи (`insert`), не можуть читати чи змінювати чужі дані.
- Читати список реєстрацій може лише той, хто увійшов через `/admin` під обліковим записом Supabase Auth.
- Геопозиція та номер телефону відвідувача — персональні дані. Перед запуском рекомендується додати на форму реєстрації коротке пояснення, навіщо збираються дані, і за потреби — окрему згоду на обробку персональних даних (checkbox) відповідно до вимог законодавства про захист персональних даних.
